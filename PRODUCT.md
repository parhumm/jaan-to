# Product

## Register

brand

## Users

READY serves solo developers and non-technical AI developers who use Claude Code or Codex on a laptop and want AI-generated changes to be easier to inspect, constrain, recover, and trust. Visitors may be capable builders without deep command-line or software infrastructure experience, so the product must explain its value without assuming systems expertise.

## Product Purpose

READY is a local, single-user development control plane for AI-assisted coding. It adds deterministic workflow boundaries around Claude Code and Codex: isolated workspaces, explicit policy, patch-only handoff, verification, review, durable run history, and recovery. The public landing page should help a visitor understand why this layer exists, judge its practical benefits and limits, install the early-test release, and star the GitHub repository.

Success means a visitor can distinguish READY from using an AI coding agent directly, understands that READY does not make the model smarter, and feels confident trying it on a disposable or low-risk project first.

## Brand Personality

Warm, kinetic, and audacious. READY should feel like an experimental instrument made by a careful builder: energetic enough to invite exploration, precise enough to earn trust, and candid about what is not finished.

## Anti-references

Avoid generic dark developer-tool pages, neon cyberpunk AI imagery, vague autonomous-agent promises, repetitive feature-card grids, terminal cosplay, inflated productivity claims, and enterprise-security language that the current local early-test release cannot support. Do not imitate Anthropic visually; borrow its human warmth and clarity only.

## Design Principles

1. Show the control loop, not abstract AI magic.
2. Lead with the practical difference between direct agent use and a guarded READY run.
3. Make installation the primary action and GitHub trust the secondary action.
4. State limits beside benefits so early adopters can make an informed choice.
5. Translate technical safety mechanisms into outcomes a solo builder can feel.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Preserve full keyboard access, visible focus, sufficient contrast, semantic landmarks, readable line lengths, reduced-motion behavior, and a responsive experience from small phones through large desktop displays. Explain technical concepts in plain language without hiding precise details from experienced developers.
